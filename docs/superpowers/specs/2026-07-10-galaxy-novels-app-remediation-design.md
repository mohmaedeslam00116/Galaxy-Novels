# Galaxy Novels App Remediation Design

## الهدف

إصلاح جميع المشكلات المؤكدة في تطبيق Flutter الحالي دون إعادة كتابة واسعة أو تغيير قرار المنتج الخاص بقسم «آخر التحديثات». يجب أن تنتهي الجولة بتطبيق Android قابل للبناء، مجموعة اختبارات ناجحة، وحدود واضحة بين بيانات الضيف وبيانات الحسابات.

## النطاق

تشمل الجولة:

- توقيع Android Release وإعدادات AdMob الخاصة بـAndroid.
- موافقة الإعلانات على Android قبل أي طلب إعلان.
- تسجيل الخروج، انتهاء الجلسة، واستعادة الحساب.
- عزل سجل القراءة وتسلسل كتاباته.
- دورة حياة المؤقتات والمتحكمات والعمليات غير المتزامنة.
- مهلات الشبكة العامة واستعادة الكاش.
- سلامة فهرس التنزيلات عند انقطاع الكتابة.
- سباقات التعليقات أثناء تغيير الفرز.
- أداء أغلفة الكتالوج والقارئ الأصلي.
- اتساق اتجاه أزرار السابق والتالي وتحديث الوثائق.

لا تشمل الجولة نشر iOS أو إضافة معرفات AdMob إنتاجية له. ستعامل مستودعات الإعلانات iOS كمنصة غير مفعلة مؤقتًا، بحيث لا تهيئ SDK ولا تطلب إعلانًا حتى تُضاف إعداداته في جولة مستقلة.

## مبادئ التنفيذ

- إصلاح السبب الجذري لكل مشكلة بدل إخفاء العرض في الاختبار.
- إضافة اختبار انحدار يفشل قبل كل إصلاح سلوكي، ثم تنفيذ أقل تغيير ينجحه.
- الحفاظ على التغييرات الحالية للمستخدم وعدم إعادة تنسيق ملفات غير مرتبطة.
- عدم إدخال حزم جديدة ما دامت APIs الموجودة في Flutter و`google_mobile_ads` كافية.
- عدم تغيير فتح «آخر التحديثات»: الضغط يفتح صفحة تفاصيل الرواية.
- فشل إعدادات Release بصورة آمنة، وعدم إنتاج حزمة تبدو إنتاجية وهي موقعة بمفتاح debug.

## التصميم

### 1. Android Release

يُفصل اختيار توقيع `release` عن وجود اسم مهمة يحتوي كلمة `Release`:

- إذا كانت بيانات مفتاح الإنتاج مكتملة، يستخدمها `release`.
- إذا كان `ALLOW_DEBUG_SIGNING_IN_RELEASE=true` صريحًا، يسمح بمفتاح debug للاختبار المحلي فقط.
- خلاف ذلك لا يربط `release` بمفتاح debug، وتفشل أي مهمة تنتج artifacts لكل variants مثل `build` أو `assemble` أو أي مهمة Release برسالة واضحة.
- يظل `debug` و`profile` قابلين للبناء دون مفتاح إنتاج.

يُزال مسار `ALLOW_TEST_ADS_IN_RELEASE` الحالي لأنه لا يغيّر App ID أو Dart ad unit IDs بصورة متسقة. إصدارات Android Release تستخدم وحدات الإنتاج، بينما debug/profile تستخدم وحدات Google الاختبارية.

### 2. موافقة AdMob على Android

تضاف طبقة صغيرة داخل ميزة الإعلانات مسؤولة عن الجاهزية:

1. تطلب تحديث معلومات الموافقة عند بدء التهيئة.
2. تعرض نموذج الموافقة عند الحاجة.
3. تفحص `canRequestAds()`.
4. تهيئ `MobileAds` فقط عندما تسمح الحالة بطلب إعلان.

يعتمد كل من banner وrewarded على Future التهيئة نفسه لمنع طلبات مكررة. إذا تعذر جمع الموافقة أو لم يسمح بطلب الإعلانات، يعيد rewarded حالة `unavailable` ويعرض banner مساحة فارغة بلا استثناء غير معالج. على iOS تعيد المستودعات `unavailable`/`null` مباشرة.

### 3. دورة حياة الجلسة

تسجيل الخروج يصبح local-first:

1. يبدأ طلب إبطال الجلسة بالخادم مع نسخة headers تحتوي الرمز الحالي.
2. يمسح الرمز من العميل والتخزين الآمن وينشر حالة `guest` دون انتظار الشبكة.
3. يكمل طلب الخادم كعملية best-effort؛ فشله لا يعيد المستخدم إلى `authenticated`.
4. فشل حذف التخزين الآمن يظهر رسالة في حالة الضيف ولا يعيد فتح الحساب.

أثناء الاستعادة، تعامل استجابة 401 أو 403 وكود تسجيل الدخول المطلوب كجلسة منتهية: تمسح النسخة المحفوظة وتنتقل إلى `guest`. كما تُرفض snapshot منتهية محليًا قبل إرسالها إذا كان `expiresAt` قد مضى.

### 4. عزل سجل القراءة

يُضاف نطاق صريح لكل عملية محلية:

- `guest` للزائر.
- `user.<id>` للمستخدم المسجل.

تُخزن القيم تحت مفاتيح مثل `reading_history.v2.guest` و`reading_history.v2.user.7`. عند أول قراءة لنطاق الضيف، تُنقل قيمة `reading_history.v1` القديمة إلى الضيف فقط ثم يُحذف المفتاح القديم؛ لا تُنسب البيانات القديمة تلقائيًا لأول حساب يدخل الجهاز.

يختار `AccountReadingHistoryRepository` النطاق مرة واحدة في بداية `load` أو `record` ويمرره إلى المستودع المحلي، حتى لا يؤدي تبدل الحساب أثناء await إلى كتابة في نطاق آخر. عمليات read-modify-write لكل نطاق تمر عبر طابور تسلسلي، بينما تظل النطاقات المختلفة مستقلة.

### 5. دورة حياة الواجهة والطلبات

- يحتفظ التطبيق بـ`Timer` تهيئة الإعلانات ويلغيه عند إعادة الجدولة و`dispose`.
- يضيف `VipChaptersController` علم disposal ورقم جيل للطلب؛ لا تنشر نتيجة إلا إذا ظل الجيل نشطًا.
- ينقل `CommentComposer` اكتمال الإرسال إلى State مالك، ويفحص `mounted` قبل مسح النص أو `setState`.
- يفصل `CommentsController` جيل تحميل القائمة عن عمليات submit/vote/reaction. تغيير الفرز يلغي نتيجة التحميل القديمة فقط، ولا يحول mutation نجحت في الخادم إلى فشل محلي. تُدمج النتيجة في القائمة الحالية عندما يمكن ذلك أو يعاد التحميل.

### 6. الشبكة العامة

يقبل `PublicCacheClient` مهلة قابلة للحقن، افتراضيًا 20 ثانية. تطبق المهلة على الاتصال، انتظار الاستجابة، وقراءة الجسم، وكذلك على `JsonGet` المحقون في الاختبارات. يتحول timeout إلى فشل شبكة عادي كي يحاول العميل قراءة النسخة المحلية. لا تتغير مهلات العميل الخاص.

### 7. سلامة فهرس التنزيلات

تستخدم كتابة الفهرس ثلاثة ملفات: الهدف، `.next`، و`.bak`:

1. تكتب `.next` مع `flush`.
2. تنقل الهدف الحالي إلى `.bak` إن وجد.
3. تنقل `.next` إلى الهدف.
4. تحذف `.bak` بعد نجاح الاستبدال.

عند القراءة، إذا غاب الهدف تستعاد `.next` أولًا إن كانت صالحة، وإلا `.bak`. لا تُحذف ملفات محتوى الفصول كـorphan قبل اكتمال استعادة فهرس صالح.

### 8. الأداء والواجهة

- لا تستخدم بطاقات الكتالوج `double.infinity` لحساب `cacheWidth/cacheHeight`. تستمد أبعادًا finite من القيود، وتستخدم غلاف `medium` للبطاقات الصغيرة مع إبقاء `large` لصفحة التفاصيل.
- يخزن القارئ نتيجة `parseChapterHtml` ما دام `contentHtml` لم يتغير، ويبني كتل الفصل عبر `ListView.builder` أو slivers كسولة. إظهار الأدوات لا يعيد تحليل HTML.
- يكون السابق في جهة اليمين بسهم يمين، والتالي في جهة اليسار بسهم يسار، بما يطابق بقية واجهات RTL في التطبيق.
- يصبح User-Agent عامًا أو محددًا حسب المنصة بدل تعريف iOS بأنه Android.

### 9. التوثيق

تُحدث خطة الاختبار وتدقيق API لتقولا إن «آخر التحديثات» تفتح تفاصيل الرواية. توثق README أو خطة الاختبار أن iOS ads معطلة مؤقتًا، وأن Android Release يحتاج توقيع إنتاج صالح.

## معالجة الأخطاء

- أخطاء الإعلانات لا تتسرب كـunhandled asynchronous errors؛ تتحول إلى عدم توفر الإعلان مع رسالة المستخدم الحالية.
- أخطاء logout البعيدة لا تعيد بيانات الاعتماد بعد مسحها محليًا.
- خطأ كتابة سجل القراءة يبقى ظاهرًا لمستدعي العملية، ولا يوقف طابور العمليات اللاحقة.
- خطأ استبدال فهرس التنزيل يستعيد النسخة السابقة قبل إعادة رمي الخطأ.
- timeout الشبكة يسمح بالكاش إن كان صالحًا، وإلا يبقى الخطأ ظاهرًا لحالة إعادة المحاولة.

## استراتيجية الاختبار

تضاف اختبارات تغطي على الأقل:

- عدم بقاء Timer بعد التخلص من `GalaxyNovelsApp`.
- رفض إعداد Release غير الموقع حتى عبر مهمة `build`، وعدم ربط release بمفتاح debug افتراضيًا.
- عدم تهيئة الإعلانات أو بنائها على iOS، وعدم طلب إعلان Android قبل موافقة UMP.
- logout دون شبكة ينتهي بحالة guest ويمسح التخزين.
- 401 أثناء restore يمسح snapshot ويظهر نموذج الدخول.
- عدم ظهور سجل المستخدم A للمستخدم B، وترحيل `v1` إلى guest.
- احتفاظ عمليتي `record` متزامنتين بكلتا الروايتين.
- تجاهل استجابة VIP بعد dispose.
- عدم تنفيذ callback مؤلف التعليق بعد إزالته.
- نجاح submit ثم تغيير الفرز لا يسمح بإعادة إرسال تعليق مكرر.
- timeout عام يستخدم الكاش.
- استعادة فهرس تنزيل من `.next` أو `.bak`.
- أغلفة الكتالوج تستخدم أبعاد decode finite.
- القارئ لا يعيد parsing عند إظهار الأدوات، واتجاه أزرار التنقل موحد.

بعد الاختبارات الموجهة تُشغّل بالترتيب:

```text
dart analyze
flutter test
flutter build apk --debug --no-pub
gradlew signingReport
gradlew build --dry-run
```

## معايير القبول

- `dart analyze` بلا أخطاء أو تحذيرات.
- كل اختبارات Flutter تنجح، بما فيها الاختبارات الـ18 التي تفشل حاليًا.
- Android debug يُبنى بنجاح.
- `signingReport` لا يعرض release موقّعًا بـdebug إلا عند العلم الصريح.
- `gradlew build` يفشل بوضوح عند غياب توقيع production، بدل إنشاء Release debug-signed.
- لا يهيئ التطبيق AdMob على iOS.
- بيانات الحساب والجلسة وسجل القراءة تحقق العزل والسلوك المحدد أعلاه.
- لا تتغير الوجهة المقصودة لقسم «آخر التحديثات».
