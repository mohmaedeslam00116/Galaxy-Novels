# Galaxy Novels Catalog Design

## الهدف

بناء شاشة **المكتبة** في تطبيق مجرة الروايات كقائمة عربية كثيفة وسريعة، تعتمد على بيانات `public.catalog_manifest` من bootstrap، وتبدأ بعرض أول pack بسرعة ثم تحمل بقية أجزاء المكتبة في الخلفية.

هذه المرحلة تجعل المكتبة قابلة للاستخدام الحقيقي بدون انتظار اكتمال كل بيانات الموقع، مع إبقاء الفلاتر والترتيب محليين حسب البيانات التي يعيدها السيرفر.

## القرارات المعتمدة

- طريقة التحميل: تحميل تدريجي.
- شكل العرض الافتراضي: قائمة كثيفة، وليست جرد أغلفة.
- الفلاتر: بحث وترتيب ظاهرين دائمًا، والحالة والتصنيفات داخل Bottom Sheet.
- الترتيب الافتراضي: آخر تحديث.
- مصدر القيم: لا نعرض أي فلتر لا توجد له بيانات حقيقية في catalog packs.
- التصميم: عربي RTL، خفيف، بدون تدرجات، وبدون ازدحام كروت.

## مصدر البيانات

من bootstrap نستخدم:

```text
public.catalog_manifest
```

الـ catalog manifest يحتوي عادة:

```json
{
  "schema": 1,
  "generated": 1710000000,
  "version": "hash",
  "count": 1200,
  "part_size": 500,
  "packs": [
    "/wp-content/uploads/wor-reader-cache/app/packs/catalog-part-1-hash.json"
  ]
}
```

كل pack يحتوي:

```json
{
  "schema": 1,
  "generated": 1710000000,
  "part": 1,
  "total_parts": 3,
  "items": []
}
```

العناصر تعتمد على الحقول العامة المتاحة:

- `id`
- `title`
- `original_title`
- `url`
- `cover.thumbnail`
- `cover.medium`
- `status.key`
- `status.label`
- `genres`
- `chapters_count`
- `rating.average`
- `rating.count`
- `stats.views`
- `updated_at`
- `manifest`

لا تستخدم المكتبة REST ولا `/?s=` للتصفح أو البحث.

## تجربة التحميل التدريجي

عند فتح المكتبة:

1. يطلب التطبيق bootstrap إذا لم تكن روابط public manifests جاهزة.
2. يطلب `catalog_manifest`.
3. يحمّل أول pack من `packs`.
4. يعرض أول مجموعة روايات فورًا.
5. يبدأ تحميل بقية packs في الخلفية بالترتيب.
6. كلما وصل pack جديد، يدمجه في القائمة ويعيد تطبيق البحث والفلترة والترتيب الحاليين.

يظهر للمستخدم سطر حالة صغير عند تحميل البقية، مثل:

```text
جار تحديث المكتبة...
```

هذا السطر لا يحجب التصفح ولا يحول الشاشة إلى loading كامل.

## واجهة المكتبة

الشاشة تكون داخل تبويب `المكتبة` الحالي.

الترتيب من الأعلى إلى الأسفل:

1. حقل بحث بعرض الشاشة تقريبًا.
2. صف أدوات صغير:
   - اختيار ترتيب، والقيمة الافتراضية `آخر تحديث`.
   - زر فلاتر يفتح Bottom Sheet.
   - عداد نتائج مختصر عند وجود بحث أو فلاتر.
3. قائمة روايات lazy.
4. حالة تحميل بقية packs في أسفل/أعلى القائمة حسب المساحة.

## عنصر الرواية في القائمة

كل عنصر يظهر:

- غلاف صغير ثابت الأبعاد.
- عنوان الرواية في سطر واحد مع ellipsis.
- تصنيفين كحد أقصى كنص مختصر.
- الحالة إذا وجدت.
- عدد الفصول إذا كان أكبر من صفر.
- تاريخ آخر تحديث إذا كان قابلًا للعرض.
- متوسط التقييم أو المشاهدات لا يظهران افتراضيًا داخل العنصر حتى لا تزحم القائمة، لكن يستخدمان في الترتيب.

شكل العنصر يكون صفًا بسيطًا مع فاصل هادئ، وليس كرتًا ثقيلًا. الغلاف له radius بسيط ومتوافق مع بطاقات الرئيسية.

## البحث

البحث محلي على البيانات المحملة حاليًا.

الحقول التي يبحث فيها:

- `title`
- `original_title`
- أسماء التصنيفات
- اسم المؤلف أو المترجم إذا أصبح متاحًا في model لاحقًا

التطبيع العربي المستخدم:

- تحويل `أ/إ/آ/ٱ` إلى `ا`.
- تحويل `ى/ئ` إلى `ي`.
- تحويل `ؤ` إلى `و`.
- تحويل `ة` إلى `ه`.
- حذف التشكيل والتطويل.
- تحويل النص إلى lowercase.
- استبدال غير الحروف والأرقام بمسافات.

البحث لا يرسل أي طلبات شبكة أثناء الكتابة.

## الترتيب

الترتيب الظاهر دائمًا أعلى القائمة.

القيم:

- `آخر تحديث`، الافتراضي.
- `الأكثر مشاهدة`.
- `الأعلى تقييمًا`.
- `عدد الفصول`.
- `العنوان`.

إذا كان حقل الترتيب ناقصًا في بعض العناصر، توضع هذه العناصر بعد العناصر التي تحتوي قيمة صالحة، مع الحفاظ على ترتيب مستقر قدر الإمكان.

## الفلاتر

زر الفلاتر يفتح Bottom Sheet.

الفلاتر داخل الـ sheet:

- الحالة، من `status.label`.
- التصنيفات، من `genres.name`.

القواعد:

- لا يظهر فلتر الحالة إذا لم توجد حالتان مميزتان على الأقل.
- لا يظهر فلتر التصنيفات إذا لم توجد تصنيفات.
- قيم الفلاتر تستخرج من البيانات المحملة وتتحدث مع وصول packs جديدة.
- عند تفعيل فلتر غير موجود لاحقًا بسبب تغيير البيانات، يزال من الاختيار النشط.

الـ Bottom Sheet يحتوي أزرار:

- تطبيق.
- مسح.

لا نضيف فلاتر البلد، المؤلف، أو المترجم في هذه المرحلة إلا إذا ظهرت الحاجة لاحقًا.

## حالات الشاشة

### Loading أولي

يعرض صفوف skeleton خفيفة بأبعاد ثابتة بدل spinner كبير.

### Empty

إذا لم ترجع أي عناصر:

```text
لا توجد روايات في المكتبة الآن
```

### No Results

إذا كان هناك بحث أو فلاتر ولا توجد نتائج:

```text
لا توجد نتائج مطابقة
```

مع زر:

```text
مسح البحث والفلاتر
```

### Error

إذا فشل تحميل manifest أو أول pack ولا توجد بيانات محفوظة:

```text
تعذر تحميل المكتبة الآن
```

مع زر:

```text
إعادة المحاولة
```

إذا فشل pack لاحق أثناء وجود بيانات معروضة، لا تسقط الشاشة. يظهر تنبيه صغير غير مزعج مع إمكانية إعادة المحاولة لاحقًا.

## الأداء

- القائمة تستخدم lazy rendering.
- البحث يستخدم debounce قصيرًا، تقريبًا 200 إلى 300ms.
- أبعاد الأغلفة ثابتة لتجنب اهتزاز الواجهة.
- تحميل packs الخلفية متسلسل ومحدود، لا يفتح طلبات كثيرة دفعة واحدة.
- عند وجود catalog كبير، لا ننشئ widgets لكل العناصر مرة واحدة.
- أي حسابات فلترة/ترتيب يجب أن تبقى خفيفة؛ إذا أصبحت ثقيلة لاحقًا يمكن نقلها إلى isolate، لكن هذا خارج نطاق المرحلة الحالية.

## قابلية iOS لاحقًا

التصميم لا يستخدم Android-only patterns. Bottom Sheet، القوائم، وحقل البحث كلها قابلة للتكييف لاحقًا مع iOS. لا نستخدم WebView أو APIs خاصة في شاشة المكتبة.

## الاختبارات المطلوبة

اختبارات unit:

- parsing لـ catalog manifest.
- parsing لـ catalog pack.
- parsing لعناصر الروايات المختصرة.
- التطبيع العربي للبحث.
- فلترة الحالة والتصنيفات.
- ترتيب آخر تحديث، المشاهدات، التقييم، عدد الفصول، والعنوان.

اختبارات repository:

- تحميل أول pack يعيد بيانات قابلة للعرض.
- تحميل بقية packs يدمج العناصر بدون حذف الموجود.
- فشل pack لاحق لا يمسح البيانات المحملة.

اختبارات widget:

- شاشة المكتبة تعرض loading أولي.
- تعرض عناصر catalog.
- البحث يقلل النتائج محليًا.
- تغيير الترتيب يغير ترتيب العناصر.
- فتح Bottom Sheet للفلاتر وتطبيق فلتر حالة.
- حالة no results تظهر مع زر مسح.

## خارج النطاق

- صفحة تفاصيل الرواية.
- فتح الفصل أو القارئ.
- حفظ catalog كامل offline بآلية cache متقدمة.
- pagination UI يدوي.
- grid view للمكتبة.
- فلاتر المؤلف، المترجم، البلد.
- REST للبحث أو المكتبة.

## معايير القبول

- تبويب المكتبة لا يعود شاشة مؤقتة.
- أول pack يظهر بدون انتظار بقية packs.
- البحث والترتيب يعملان محليًا.
- فلتر الحالة والتصنيفات يظهران ديناميكيًا حسب البيانات.
- الترتيب الافتراضي هو آخر تحديث.
- التصميم قائمة كثيفة وخفيفة، بدون تدرجات وبدون كروت كثيرة.
- `dart analyze` ينجح.
- اختبارات unit/widget الخاصة بالمكتبة تنجح.
