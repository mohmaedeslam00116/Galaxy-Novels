# تصميم تحديث ملف الحساب بعد مزامنة القراءة

## الهدف

تحديث XP والرتبة المعروضين في شاشة «حسابي» من بيانات السيرفر بعد اكتمال مزامنة نشاط القراءة، وكذلك عند فتح شاشة الحساب، من دون حساب XP محليا أو إعادة بناء جلسة تسجيل الدخول كاملة.

## الوضع الحالي

- نموذج `AuthUser` يحتوي بالفعل على بيانات VIP وXP والرتبة.
- استجابة تسجيل الدخول و`GET /session` تملآن هذه البيانات.
- شاشة الحساب تعرض الرتبة وإجمالي XP وعدد الفصول المقروءة.
- `POST /reading/sync` يرسل نشاط القراءة، لكنه لا يحدّث `AuthUser` بعد نجاحه.
- القالب يوفر `GET /me` كمسار محمي يعيد كائن `user` محدثا، بما فيه XP والرتبة.

## القرار المعماري

نوسّع `AuthRepository` بدالة `refreshProfile()`، وينفذها `SessionAuthRepository` باستخدام `GET /me`. يبقى مستودع الحساب المصدر الوحيد لحالة المستخدم، ولا تنشأ طبقة مستقلة لملف الحساب في هذه المرحلة.

هذا الاختيار يحافظ على تدفق أحادي الاتجاه:

1. `SessionAuthRepository` يطلب بيانات المستخدم ويحدث `AuthSessionState`.
2. `AccountSessionView` يستمع إلى المستودع ويعيد عرض البيانات الجديدة.
3. `SyncedReadingActivityRepository` يطلب تحديث الملف بعد تفريغ queue بنجاح، ولا يعدل بيانات الحساب مباشرة.

## عقد البيانات

يستخدم التطبيق:

```text
GET /wp-json/wor-reader-app/v1/me
```

والشكل المطلوب من الاستجابة:

```json
{
  "user": {
    "id": 7,
    "display_name": "قارئ المجرة",
    "avatar": "https://example.com/avatar.jpg",
    "vip": {
      "active": false,
      "tier": "",
      "label": "",
      "expires_at": ""
    },
    "xp": {
      "total": 320,
      "today": 20,
      "seconds_total": 900,
      "chapters_total": 14,
      "rank": {
        "level": 3,
        "display": "مستكشف"
      }
    }
  }
}
```

يُعاد استخدام `AuthUser.fromJson`. تُرفض الاستجابة إذا كان `user` مفقودا، أو إذا كان المعرف غير صالح، أو إذا كان معرف المستخدم لا يطابق الحساب الذي بدأ الطلب.

## سياسة التحديث

### عند فتح الحساب

تستدعي شاشة «حسابي» `refreshProfile()` عندما تكون الجلسة مصادقة. تبقى البيانات الحالية ظاهرة أثناء الطلب، ولا تتحول الشاشة إلى loading.

### بعد مزامنة القراءة

بعد نجاح رفع آخر دفعة وحذف أحداثها محليا، يطلب `SyncedReadingActivityRepository` تحديث ملف الحساب فقط عندما تصبح queue الخاصة بالمستخدم فارغة. لا يُطلب `/me` بعد كل دفعة وسيطة.

### منع الطلبات الزائدة

- مدة التهدئة `60` ثانية لكل جلسة حساب.
- الطلبات المتزامنة تندمج في Future واحدة.
- أي طلب تحديث يصل أثناء التهدئة لا ينشئ طلبا فوريا؛ يسجل حاجة إلى التحديث ويجدول طلبا واحدا عند نهاية المدة.
- إذا جرى تأجيل الطلب بسبب التهدئة، تنتهي `refreshProfile()` مباشرة بعد نجاح الجدولة ولا تحجز مستدعيها حتى يعمل المؤقت.
- لا يبدأ طلب مؤجل بعد تسجيل الخروج أو تبديل الحساب.
- تُصفّر حالة التهدئة والطلب المؤجل عند تغيّر هوية المستخدم أو تسجيل الخروج.
- يبدأ حساب التهدئة عند محاولة الطلب، حتى لا يؤدي فشل الشبكة إلى حلقة طلبات سريعة.

## إدارة الحالة

- يحتفظ `AuthSessionState` بالمستخدم الحالي أثناء تحديث الملف.
- عند نجاح `/me` ينشر المستودع حالة `authenticated` بالمستخدم المحدث.
- يحافظ التحديث الناجح على `noticeMessage` الحالية ما دام الحساب وحالة المصادقة لم يتغيرا.
- إذا تغيّرت الجلسة أو معرف المستخدم قبل وصول الاستجابة، تُهمل الاستجابة.
- لا يُحفظ XP في التخزين الآمن؛ تبقى بيانات الجلسة الحساسة فقط هي المخزنة كما في النظام الحالي.

## معالجة الأخطاء

- يستخدم الطلب مسار العميل الذي يجدد nonce مرة واحدة عند انتهاء nonce.
- فشل الشبكة أو `5xx` أو JSON غير صالح يبقي بيانات الحساب القديمة ولا يحول الشاشة إلى حالة فشل.
- `401` بعد محاولة تجديد nonce يشغّل `restoreSession()` للتحقق من انتهاء الجلسة فعليا.
- الخطأ الخلفي لا يعطل نجاح مزامنة نشاط القراءة ولا يعيد الأحداث التي قبلها السيرفر إلى queue.
- لا تظهر رسالة مزعجة بعد كل فشل خلفي؛ المحاولة التالية تأتي من فتح الحساب أو من دورة مزامنة لاحقة.

## واجهة الحساب

تبقى بنية شاشة الحساب الحالية، مع عرض معلومات السيرفر التالية بوضوح:

- اسم المستخدم والصورة أو الحرف البديل.
- اسم الرتبة تحت اسم المستخدم.
- إجمالي XP.
- XP اليوم.
- عدد الفصول المقروءة.
- حالة VIP عند توفرها.

تُعرض الإحصاءات كمجموعة مضغوطة متجاوبة، دون كروت متداخلة أو حركة ثقيلة. لا نضيف شاشة نقاط منفصلة في هذه المرحلة.

## الاختبارات

### اختبارات البيانات والمستودع

- تحليل استجابة `/me` الصحيحة.
- رفض استجابة بلا مستخدم أو بهوية غير مطابقة.
- تحديث المستخدم مع بقاء حالة الجلسة مصادقة.
- دمج طلبات التحديث المتزامنة.
- تطبيق تهدئة 60 ثانية وجدولة تحديث واحد مؤجل.
- الاحتفاظ بالبيانات القديمة عند فشل الشبكة أو البيانات.
- استعادة الجلسة عند `401` النهائي.
- تجاهل استجابة حساب قديم بعد تبديل الحساب.

### اختبارات التكامل

- طلب تحديث الملف بعد تفريغ queue بنجاح.
- عدم طلب الملف بعد دفعة ما زالت تتبعها أحداث معلقة.
- عدم طلب الملف عند فشل مزامنة القراءة.

### اختبارات الواجهة

- استدعاء التحديث عند فتح شاشة الحساب لمستخدم مصادق.
- إظهار إجمالي XP وXP اليوم والفصول والرتبة.
- عدم وجود overflow على عرض هاتف ضيق.

## خارج النطاق

- حساب XP أو الرتبة داخل التطبيق.
- شاشة مستقلة للنقاط أو سجل المكافآت.
- نظام النقاط الخاص بالتنزيلات.
- الإعلانات.
- تحديثات دورية في الخلفية عندما يكون التطبيق مغلقا.

## معيار الاكتمال

تُعد الميزة مكتملة عندما تتحدث بيانات XP والرتبة من `/me` بعد آخر مزامنة قراءة ناجحة وعند فتح الحساب، مع منع الطلبات المكررة، والحفاظ على البيانات القديمة في حالات الفشل، ونجاح التحليل والاختبارات وبناء APK.
