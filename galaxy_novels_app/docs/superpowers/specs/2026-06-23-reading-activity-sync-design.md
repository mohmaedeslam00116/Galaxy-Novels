# تصميم مزامنة نشاط القراءة

## الهدف

إضافة قياس موثوق وخفيف لنشاط القراءة داخل القارئ Native، وحفظ أحداث الحساب محليا ثم إرسالها إلى `POST /reading/sync` دون فقدها عند انقطاع الشبكة أو مضاعفة الوقت وXP عند إعادة المحاولة.

## النطاق المعتمد

- القياس والمزامنة للحساب المسجل فقط.
- قراءة الضيف لا تنشئ أحداثا ولا تُنسب إلى حساب يسجل الدخول لاحقا.
- `open_seconds` يقيس مدة ظهور الفصل بينما التطبيق في الواجهة.
- `active_seconds` يقيس مدة القراءة النشطة فقط.
- يرسل `active_seconds` إلى حقل الطلب `reading_seconds` الذي يعتمد عليه القالب.
- فتح الفصل واللمس والتمرير تمدد النشاط لمدة 60 ثانية.
- يتوقف العد عند انتقال التطبيق إلى الخلفية، ويستأنف بعد عودته عند حدوث تفاعل جديد.
- تقدم الفصل مستمد من موضع التمرير داخل الفصل نفسه من 0 إلى 100.
- الفصل مكتمل عند وصول التقدم إلى 92%، بما يطابق قاعدة القالب.

## عقد السيرفر

المسار الخاص هو:

```text
POST /wp-json/wor-reader-app/v1/reading/sync
```

يرسل التطبيق جسما بالشكل التالي:

```json
{
  "items": [
    {
      "event_id": "app:7:501:1782217800000000:a1b2c3d4",
      "object_type": "chapter",
      "object_id": 501,
      "parent_id": 42,
      "reading_seconds": 48,
      "open_seconds": 60,
      "progress": 37,
      "completed": false,
      "views": 1,
      "read_at": "2026-06-23T12:30:00.000Z"
    }
  ]
}
```

الحدود المؤكدة من القالب:

- 50 حدثا كحد أقصى للطلب.
- 32KB كحد أقصى لحجم الطلب.
- 300 ثانية كحد أقصى لـ`reading_seconds` في الحدث الواحد.
- 900 ثانية كحد أقصى لـ`open_seconds` في الحدث الواحد.
- طلب عادي واحد لكل مستخدم كل 20 ثانية.
- `event_id` بطول أقصى 80 محرفا، ويستخدمه السيرفر لمنع احتساب الحدث مرتين.

لن يستخدم التطبيق `final: true` لتجاوز تحديد المعدل. الخروج أو الانتقال للخلفية يحفظ الحدث محليا، ثم ترسله دورة المزامنة العادية.

## البنية

### Domain

`ReadingActivityEvent` يمثل حدثا ثابتا غير قابل للتعديل بعد إنشائه. يحتوي معرف الحساب والفصل والرواية والزمن والتقدم، ويدعم JSON للتخزين وJSON مختلفا لطلب السيرفر.

`ReadingSessionTracker` مسؤول عن الحساب فقط. يستقبل الوقت الحالي وإشارات التفاعل والتقدم وتغير حالة التطبيق، ويعيد لقطة قابلة للتحويل إلى حدث عند checkpoint. لا يعرف الشبكة أو `SharedPreferences` أو Flutter widgets.

### Data

`ReadingActivityStore` عقد تخزين لطابور أحداث مستقل لكل `userId`.

`SharedPreferencesReadingActivityStore` يحفظ JSON تحت مفتاح يتضمن `userId`. يحتفظ بحد أقصى 500 حدث لكل حساب، ويحذف الأقدم فقط عند تجاوز الحد لمنع نمو التخزين بلا سقف.

`ReadingActivityRemoteService` يرسل دفعات حتى 50 حدثا باستخدام `PrivateApiClient.postAuthenticatedWithNonceRefresh`.

`SyncedReadingActivityRepository` هو مصدر الحقيقة للطابور. ينشئ جلسات مرتبطة بالحساب الموجود وقت بدء الفصل، يحفظ checkpoints، يمنع مزامنة حساب داخل جلسة حساب آخر، ويزيل الدفعة بعد استجابة HTTP ناجحة سواء احتسبها السيرفر كأحداث جديدة أو مكررة.

### Presentation

`ReaderScreen` يراقب دورة حياة التطبيق ويملك جلسة الفصل الحالية. ينهي checkpoint قبل تغيير الفصل وعند الانتقال إلى الخلفية وعند التخلص من الشاشة.

`NativeReaderContent` يرسل إشارات اللمس والتمرير ونسبة تقدم الفصل إلى `ReaderScreen`. لا ينفذ تخزينا أو طلبات شبكة.

## تدفق الجلسة

1. يحمل القارئ الفصل بنجاح.
2. يطلب `ReaderScreen` بدء جلسة نشاط باستخدام `novelId` و`chapterId`.
3. إذا لم توجد جلسة حساب مصادق عليها، يعيد المستودع جلسة فارغة ولا يسجل شيئا.
4. يعتبر فتح الفصل أول تفاعل ويبدأ نافذة نشاط مدتها 60 ثانية.
5. يحدث التمرير التقدم ويمدد نافذة النشاط.
6. كل 60 ثانية من القراءة النشطة ينشأ checkpoint ثابت ويحفظ في طابور الحساب.
7. تغيير الفصل أو إخفاء التطبيق أو إغلاق القارئ ينشئ checkpoint أخيرا إذا احتوى زمنا أو تقدما قابلا للإرسال.
8. بعد الحفظ يحاول المستودع إرسال أقدم دفعة عندما يسمح فاصل 20 ثانية.
9. النجاح يحذف الدفعة، والفشل يبقيها بلا تعديل للمحاولة التالية.

## الدقة ومنع التكرار

- كل checkpoint يحصل على `event_id` جديد قبل التخزين ولا يتغير عند إعادة الإرسال.
- لا تُعدّل أحداث موجودة بعد محاولة إرسالها.
- الحدث الأول في جلسة الفصل يحمل `views: 1`، والأحداث اللاحقة تحمل `views: 0`.
- لا ينشأ حدث يعتمد على `open_seconds` وحده؛ يلزم مشاهدة أولى أو نشاط فعلي أو تقدم أو اكتمال، لأن القالب يتجاهل حدث الفتح الخالي من هذه الإشارات.
- التقدم المرسل هو أعلى تقدم وصل إليه checkpoint.
- checkpoint الدوري لا يعمل كل ثانية؛ يستخدم مؤقتا واحدا كل 60 ثانية أثناء وجود القارئ فقط.
- الحساب يعتمد فروق الزمن بين الإشارات، وليس مؤقتا يعيد بناء الواجهة.
- القيم تقيد محليا قبل الإرسال إلى حدود السيرفر.

## تبديل الحساب ودورة الحياة

- الجلسة ترتبط بـ`userId` الموجود عند بدايتها.
- الحدث المكتمل يحفظ في طابور ذلك الحساب حتى لو تغير الحساب قبل الحفظ.
- لا يرسل المستودع إلا طابور الحساب المصادق عليه حاليا.
- تسجيل الخروج يوقف جدولة الإرسال ولا يحذف الطابور.
- عودة الحساب نفسه لاحقا تستأنف إرسال أحداثه.
- الانتقال إلى `inactive` أو `paused` يوقف الوقت المفتوح والنشط وينشئ checkpoint محليا.
- العودة إلى `resumed` تبدأ مقطع فتح جديد، لكن النشاط ينتظر تفاعلا جديدا.

## معالجة الأخطاء

- انقطاع الشبكة و`429` و`5xx`: الاحتفاظ بالدفعة وإعادة المحاولة في دورة لاحقة.
- انتهاء nonce: يستخدم العميل التجديد الموحد ثم يعيد الطلب مرة واحدة.
- `401`: الاحتفاظ بالطابور وطلب استعادة حالة الجلسة.
- استجابة ناجحة: إزالة عناصر الدفعة كاملة؛ العناصر التي تجاهلها السيرفر غير صالحة وفقا لعقده، وتكرارها لن يصلحها.
- بيانات تخزين تالفة: تجاهل الحمولة التالفة لذلك الحساب والبدء بطابور فارغ دون التأثير في بقية الحسابات.

## الاختبارات

### Unit

- احتساب `open_seconds` و`active_seconds` مع نافذة الخمول 60 ثانية.
- إيقاف الحساب في الخلفية واستئنافه بعد تفاعل جديد.
- حساب تقدم التمرير وتحديد الاكتمال عند 92%.
- ثبات `event_id` خلال إعادة المحاولة.
- حفظ واستعادة طابور مستقل لكل حساب.
- إرسال 50 حدثا كحد أقصى وإبقاء الباقي.
- الاحتفاظ بالدفعة عند الشبكة و`429` وإزالتها عند النجاح.
- عدم إرسال طابور حساب سابق بعد تبديل الحساب.

### Widget

- تمرير القارئ يرسل النشاط ونسبة التقدم إلى جلسة القراءة.
- تغيير الفصل ينهي checkpoint السابق قبل بدء الجديد.
- قارئ الضيف لا ينشئ أحداثا.

### Regression

- اختبارات سجل القراءة والمفضلة وتجديد nonce تبقى ناجحة.
- `flutter analyze` و`flutter test` و`flutter build apk --debug` تنجح قبل الإكمال.

## خارج النطاق

- عرض XP في الواجهة؛ يأتي في الخطوة التالية من بيانات السيرفر.
- مزامنة قراءة الضيف.
- إرسال نشاط في الخلفية عبر Android WorkManager أو iOS Background Tasks.
- شاشة للمستخدم تعرض الطابور أو تفاصيل القياس.
- تعديل قواعد XP أو حدود السيرفر.

## معيار الاكتمال

تعد مرحلة نشاط القراءة مكتملة عندما يقيس القارئ جلسة الحساب، ويحفظ أحداثا ثابتة محليا، ويرسلها بدفعات آمنة إلى `/reading/sync` مع عمل offline وتبديل الحساب، ثم تحدث `docs/app_api_gap_audit.md` لتعليم بند queue والمزامنة كمكتمل مع إبقاء عرض XP كبند مستقل غير مكتمل.
